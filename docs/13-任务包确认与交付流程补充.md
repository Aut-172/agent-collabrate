# 任务包确认与交付流程补充

## 1. 核心决策

成员不需要在提交交付时重新上传任务包。

任务包由平台保存为不可变版本，成员交付时只提交：

- `packageId`
- `packageVersion`
- `packageHash`
- Final Report
- 分支名
- Commit SHA
- Pull Request URL

平台根据 `packageId` 从数据库读取真实任务包内容，不信任客户端重新上传的完整任务包。

## 2. 正常流程

```text
平台生成 Task Package v3
  -> 成员查看、下载或复制 v3
  -> 成员让本地 Agent 读取 v3
  -> 成员点击“确认并开始开发”
  -> 平台记录 packageId、version、hash 和确认时间
  -> 本地 Agent 开发、测试、Commit、Push
  -> 本地 Agent 输出 Final Report
  -> 成员审阅 Final Report 和本地 Diff
  -> 成员进入平台交付页面
  -> 平台自动检查任务包版本
  -> 成员提交 Final Report 和 Git 交付信息
  -> 平台登记 TaskDelivery 并异步校验 Git/PR
  -> Git 校验成功后，平台按当前 Commit SHA 异步同步 CI
```

## 3. 开始开发时的确认

`POST /api/tasks/{id}/packages/{version}/confirm`

平台保存：

```text
task_id
package_id
package_version
content_hash
user_id
confirmation_type
confirmed_at
```

确认表示：

> 成员已经看到当前任务包，并确认按该版本继续开发。

在平台不接管成员本地 Agent 的 MVP 中，平台无法证明本地 Agent 实际读取了哪个文件。因此使用以下组合约束：

1. 平台确认记录；
2. 任务包内容哈希；
3. Final Report 回传任务包引用；
4. 提交交付时服务端强校验。

## 4. 交付时的强校验

平台必须验证：

```text
当前 Task Package = 成员最近确认的 Task Package
当前 Task Package = Final Report 引用的 Task Package
当前 Task Package = TaskDelivery 引用的 Task Package
```

三者需要同时匹配：

```text
packageId
packageVersion
packageHash
```

此外还要验证：

- 提交人是当前任务负责人；
- 任务包状态为 `CURRENT`；
- Final Report 通过 JSON Schema；
- 提交的分支、Commit 和 PR 字段与 Final Report 一致。

Commit 是否存在且属于目标仓库、PR 是否属于目标仓库、PR head SHA 是否与提交 Commit 一致，必须在登记交付后由 `GIT_SYNC` 后台任务通过 Git Provider 异步校验。校验结果写入运行记录；只有校验成功才能创建当前 Commit SHA 对应的 CI 同步任务。

校验失败时返回：

```text
409 TASK_PACKAGE_STALE
```

并返回当前任务包、成员已确认版本和新旧版本差异地址。

## 5. 任务包更新

如果任务包没有更新，成员无需重新上传，直接交付。

如果任务包更新：

```text
v3 = STALE
v4 = CURRENT
```

成员必须：

1. 查看 v3 到 v4 的差异；
2. 下载或复制 v4；
3. 让本地 Agent 重新读取 v4；
4. 点击“确认 v4 并继续开发”；
5. 再提交交付。

平台不自动修改成员本地分支，也不自动判断成员是否需要回退代码。

## 6. Final Report

Final Report 是本地开发过程的结构化说明，不是平台认定完成的唯一依据。

最少包含：

```json
{
  "schemaVersion": "1.0",
  "taskId": "TASK-001",
  "packageId": 3003,
  "packageVersion": 3,
  "packageHash": "sha256:...",
  "outcome": "READY_FOR_REVIEW",
  "summary": "已实现任务目标。",
  "changedFiles": [],
  "tests": [],
  "git": {
    "branchName": "agent/wf-42/task-001",
    "commitSha": "abcdef123456",
    "pullRequestUrl": "https://github.com/example/repo/pull/18"
  },
  "acceptanceCriteria": [],
  "unresolvedIssues": [],
  "outOfScopeChanges": [],
  "blockers": []
}
```

Final Report 用于：

- 说明实际修改内容；
- 记录本地验证命令；
- 对照验收标准；
- 记录未解决问题；
- 支持 Leader 审阅、返工和审计。

Final Report 中声称测试通过，不等同于 CI 通过。任务完成仍必须依赖当前 Commit 的 CI 结果。

## 7. 交付页面

交付页面采用分步确认：

```text
1. 任务包
2. Final Report
3. Git 信息
4. 平台校验
5. 提交交付
```

提交前显示：

```text
任务包版本：v3
任务包哈希：sha256:...
最近确认版本：v3
分支：agent/wf-42/task-001
Commit：abcdef1
PR：#18
Git 校验：通过
CI 状态：等待中
```

前端可以从 Final Report 自动提取分支、Commit 和 PR，但最终以服务端校验结果为准。
