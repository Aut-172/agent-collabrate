# MVP 数据库表设计

## 1. 设计原则

本文件将领域实体落到 PostgreSQL 表级别，作为 Flyway migration 和 JPA 实体实现的依据。

- `users` 只保存全局登录身份；
- 项目角色和项目能力画像保存在 `project_members`；
- Leader 和 Member 都可以成为任务负责人；
- 文档、任务包、任务分配、阻塞、Git/CI 和审计记录保留历史；
- 代码上下文使用版本化记录，Agent 生成文档时绑定具体上下文版本；
- 复杂结构使用 `JSONB`；
- 时间字段统一使用 `TIMESTAMPTZ`；
- 状态使用 `VARCHAR` 加应用层 Enum 和数据库约束；
- 关键写操作使用唯一约束、事务和乐观锁保证一致性。

## 2. 用户和项目

### 2.1 users

保存全局登录身份，不保存项目角色和项目能力画像。

| 字段 | 类型 | 约束/说明 |
|---|---|---|
| id | BIGINT | PK |
| username | VARCHAR(50) | NOT NULL、UNIQUE |
| password_hash | VARCHAR(255) | NOT NULL |
| enabled | BOOLEAN | NOT NULL，默认 TRUE |
| created_at | TIMESTAMPTZ | NOT NULL |
| updated_at | TIMESTAMPTZ | NOT NULL |

### 2.2 projects

| 字段 | 类型 | 约束/说明 |
|---|---|---|
| id | BIGINT | PK |
| name | VARCHAR(100) | NOT NULL |
| repository_url | VARCHAR(500) | NOT NULL |
| git_provider | VARCHAR(30) | NOT NULL，MVP 为 `github` |
| default_branch | VARCHAR(100) | NOT NULL，默认 `main` |
| latest_context_commit | VARCHAR(100) | 最近成功同步的代码上下文 Commit，可为空 |
| ci_status | VARCHAR(30) | `CI_NOT_CONFIGURED`、`CI_REQUIRED`，默认 `CI_NOT_CONFIGURED` |
| status | VARCHAR(20) | `ACTIVE`、`ARCHIVED` |
| created_by | BIGINT | FK users.id，NOT NULL |
| created_at | TIMESTAMPTZ | NOT NULL |
| updated_at | TIMESTAMPTZ | NOT NULL |
| version | BIGINT | 乐观锁 |

约束：

```sql
CHECK (ci_status IN ('CI_NOT_CONFIGURED', 'CI_REQUIRED'))
```

### 2.3 project_members

这是项目成员实体，也是项目权限和 Agent 分工画像的归属实体。

| 字段 | 类型 | 约束/说明 |
|---|---|---|
| id | BIGINT | PK |
| project_id | BIGINT | FK projects.id，NOT NULL |
| user_id | BIGINT | FK users.id，NOT NULL |
| project_role | VARCHAR(20) | `LEADER`、`MEMBER`，NOT NULL |
| capability_profile | JSONB | 成员自填的项目能力/职责画像 |
| profile_version | INT | NOT NULL，默认 0 |
| profile_completed | BOOLEAN | NOT NULL，默认 FALSE |
| profile_updated_at | TIMESTAMPTZ | 可为空 |
| weekly_capacity_points | INT | 每周可投入的相对工作量容量，建议范围 1-40 |
| availability | VARCHAR(30) | `FULL_TIME`、`PART_TIME`、`LIMITED` 等可分配状态 |
| joined_at | TIMESTAMPTZ | NOT NULL |
| left_at | TIMESTAMPTZ | 可为空 |
| status | VARCHAR(20) | `ACTIVE`、`REMOVED` |
| version | BIGINT | 乐观锁 |

约束：

```sql
UNIQUE (project_id, user_id)
CHECK (project_role IN ('LEADER', 'MEMBER'))
CHECK (status IN ('ACTIVE', 'REMOVED'))
CHECK (weekly_capacity_points IS NULL OR weekly_capacity_points BETWEEN 1 AND 40)
```

活跃成员只有在以下条件同时满足时才可以成为任务候选人：

```text
status = ACTIVE
profile_completed = TRUE
capability_profile IS NOT NULL
```

建议的 `capability_profile` 结构：

```json
{
  "summary": "负责后端服务和认证模块",
  "responsibilities": ["后端架构", "接口开发", "代码评审"],
  "skills": ["Java", "Spring Boot", "PostgreSQL"],
  "experience": ["认证系统", "REST API"],
  "preferredTaskTypes": ["后端开发", "数据库设计"],
  "limitations": ["不负责前端视觉设计"],
  "availability": "PART_TIME",
  "weeklyCapacityPoints": 13,
  "notes": "每周可投入约 15 小时"
}
```

该 JSON 必须通过 JSON Schema。不能仅依靠一段自由文本，否则 Agent 很难稳定使用，也不利于前端校验。

### 2.4 member_profile_versions

`project_members.capability_profile` 保存当前画像，本表保存历史版本。

| 字段 | 类型 | 约束/说明 |
|---|---|---|
| id | BIGINT | PK |
| project_member_id | BIGINT | FK project_members.id |
| version_no | INT | NOT NULL |
| profile | JSONB | 该版本完整画像 |
| changed_by | BIGINT | FK users.id，通常为本人 |
| created_at | TIMESTAMPTZ | NOT NULL |

约束：

```sql
UNIQUE (project_member_id, version_no)
```

成员更新当前画像时，必须先写入新历史版本，再更新 `project_members` 当前值。

## 3. 工作流和文档

### 3.1 workflows

| 字段 | 类型 | 约束/说明 |
|---|---|---|
| id | BIGINT | PK |
| project_id | BIGINT | FK projects.id |
| title | VARCHAR(200) | NOT NULL |
| description | TEXT | NOT NULL |
| intent_level | VARCHAR(20) | `ARCHITECTURE`、`FEATURE`、`CHANGE` |
| completion_mode | VARCHAR(30) | `ARCHITECTURE_BASELINE`、`CI_BOOTSTRAP`、`CI_REQUIRED` |

| created_at | TIMESTAMPTZ | NOT NULL |
| updated_at | TIMESTAMPTZ | NOT NULL |

约束：

```sql
CHECK (completion_mode IN (
  'ARCHITECTURE_BASELINE',

```

`CI_BOOTSTRAP` 的“项目内只能有一个进行中实例”建议使用部分唯一索引或在事务中加项目级锁实现，不能只依赖前端按钮禁用。

## 4. 任务和交接

### 4.1 tasks

| 字段 | 类型 | 约束/说明 |
|---|---|---|
| id | BIGINT | PK |
| workflow_id | BIGINT | FK workflows.id |
| external_key | VARCHAR(50) | 工作流内唯一 |
| title | VARCHAR(200) | NOT NULL |
| description | TEXT | NOT NULL |
| effort_points | INT | `1-8`，相对工作量估算 |
| status | VARCHAR(40) | TaskStatus |
| source_plan_version | INT | 来源 Build Plan 版本 |
| source_spec_version | INT | 来源 Spec 版本 |
| branch_name | VARCHAR(200) | 当前建议分支 |
| current_package_version | INT | 当前任务包版本 |
| delivery_notes | TEXT | 可为空 |
| result_summary | TEXT | 可为空 |
| created_at | TIMESTAMPTZ | NOT NULL |
| updated_at | TIMESTAMPTZ | NOT NULL |
| version | BIGINT | 乐观锁 |

约束：

```sql
UNIQUE (workflow_id, external_key)
CHECK (effort_points BETWEEN 1 AND 8)
```

### 4.2 task_assignments

保存当前和历史分配。`assignee_user_id` 可以是 Leader，也可以是 Member。

| 字段 | 类型 | 约束/说明 |
|---|---|---|
| id | BIGINT | PK |
| task_id | BIGINT | FK tasks.id |
| assignee_user_id | BIGINT | FK users.id |
| assigned_by | BIGINT | FK users.id |
| assignment_version | INT | 任务内递增 |
| assignment_reason | TEXT | Agent 建议或 Leader 修改理由 |
| assignment_score | NUMERIC(5,4) | Agent 对匹配结果的评分，可为空 |
| profile_version | INT | 分配时的画像版本 |
| profile_snapshot | JSONB | 分配时画像快照 |
| workload_snapshot | JSONB | 分配时未完成工作量、容量和计算口径 |
| is_current | BOOLEAN | 当前分配 |
| assigned_at | TIMESTAMPTZ | NOT NULL |
| ended_at | TIMESTAMPTZ | 可为空 |

业务约束：

- `assignee_user_id` 必须是该项目的 ACTIVE 成员；
- 对应的 `profile_completed` 必须为 TRUE；
- 一个 Task 最多一条 `is_current = TRUE`；
- 重新分配不能删除旧记录；
- `profile_snapshot` 不随成员后续更新而变化；
- `workload_snapshot` 保存分配时的工作量计算依据，不随成员后续任务变化而回写。

### 4.3 task_packages

| 字段 | 类型 | 约束/说明 |
|---|---|---|
| id | BIGINT | PK |
| task_id | BIGINT | FK tasks.id |
| package_version | INT | NOT NULL |
| status | VARCHAR(20) | `CURRENT`、`STALE`、`RETIRED` |
| content_markdown | TEXT | NOT NULL |
| content_json | JSONB | NOT NULL |
| content_hash | VARCHAR(128) | NOT NULL |
| source_task_version | BIGINT | 任务版本 |
| source_plan_version | INT | Plan 版本 |
| source_spec_version | INT | Spec 版本 |
| source_profile_version | INT | 负责人画像版本 |
| base_commit | VARCHAR(100) | 代码基线 |
| code_context_version_id | BIGINT | FK code_context_versions.id，可为空 |
| context_plan_id | BIGINT | FK code_context_plans.id，可为空 |
| created_at | TIMESTAMPTZ | NOT NULL |
| superseded_by | BIGINT | 自引用，可为空 |

约束：

```sql
UNIQUE (task_id, package_version)
```

任务包必须包含负责人角色和画像摘要，但不应包含成员隐私字段或任何凭证。

### 4.4 task_package_confirmations

| 字段 | 类型 | 约束/说明 |
|---|---|---|
| id | BIGINT | PK |
| task_id | BIGINT | FK tasks.id |
| package_id | BIGINT | FK task_packages.id |
| package_version | INT | 成员确认时看到的任务包版本 |
| content_hash | VARCHAR(128) | 成员确认时看到的任务包内容哈希 |
| user_id | BIGINT | FK users.id |
| confirmation_type | VARCHAR(30) | `START_DEVELOPMENT`、`RESUME_AFTER_BLOCKER` |
| created_at | TIMESTAMPTZ | NOT NULL |

确认人必须是当前 Task 负责人；Leader 只有在自己就是负责人时才可以用该流程开始开发。
确认接口统一使用 `POST /api/tasks/{id}/packages/{version}/confirm`，服务端从不可变任务包读取并校验 `package_version` 和 `content_hash`。

### 4.5 task_deliveries

保存一次交付尝试。一次 Task 可能因为 CI 失败、任务包更新或返工而产生多条交付记录。

| 字段 | 类型 | 约束/说明 |
|---|---|---|
| id | BIGINT | PK |
| task_id | BIGINT | FK tasks.id |
| submitted_by | BIGINT | FK users.id，必须是当前负责人 |
| package_id | BIGINT | FK task_packages.id |
| package_version | INT | 提交时使用的任务包版本 |
| code_context_version_id | BIGINT | FK code_context_versions.id，提交时任务包绑定的上下文 |
| context_plan_id | BIGINT | FK code_context_plans.id，提交时任务包绑定的取证计划 |
| base_commit_sha | VARCHAR(100) | 提交时任务包声明的代码基线 |
| outcome | VARCHAR(30) | `READY_FOR_REVIEW`、`BLOCKED`、`FAILED` |
| report_json | JSONB | 本地 Agent Final Report |
| branch_name | VARCHAR(200) | NOT NULL |
| commit_sha | VARCHAR(100) | NOT NULL |
| pull_request_url | VARCHAR(500) | 可为空 |
| status | VARCHAR(30) | `SUBMITTED`、`CI_RUNNING`、`PASSED`、`FAILED`、`REJECTED` |
| rejection_reason | TEXT | 可为空 |
| submitted_at | TIMESTAMPTZ | NOT NULL |
| reviewed_at | TIMESTAMPTZ | 可为空 |

业务约束：

- `package_id` 必须属于该 Task；
- `package_version` 必须是提交时的 CURRENT 版本；
- Code Context、Context Plan 和基线 SHA 必须从服务端保存的 TaskPackage 复制，不信任客户端回传；
- `report_json` 必须通过 Final Report JSON Schema；
- `commit_sha` 必须经 Git Provider 校验；
- Final Report 中的测试结果是说明性数据，不直接改变 CI 状态；
- 每次返工创建新的 TaskDelivery，不覆盖旧交付。

## 6. Code Context

### 6.1 code_context_runs

保存 Repo Ingestion 和 Code Evidence Collection 编排运行记录，并作为异步 Outbox 的引用实体。

| 字段 | 类型 | 约束/说明 |
|---|---|---|
| id | BIGINT | PK |
| project_id | BIGINT | FK projects.id |
| requested_by | BIGINT | FK users.id，可为空 |
| run_type | VARCHAR(30) | `REPO_INGESTION`、`EVIDENCE_COLLECTION` |
| status | VARCHAR(20) | `QUEUED`、`RUNNING`、`SUCCEEDED`、`FAILED` |
| inventory_version_id | BIGINT | FK repo_inventory_versions.id，可为空 |
| context_plan_id | BIGINT | FK code_context_plans.id，可为空；证据收集时必填 |
| code_context_version_id | BIGINT | FK code_context_versions.id，可为空；证据收集成功后填写 |
| error_message | TEXT | 可为空，必须脱敏 |
| created_at | TIMESTAMPTZ | NOT NULL |
| started_at | TIMESTAMPTZ | 可为空 |
| finished_at | TIMESTAMPTZ | 可为空 |

同一项目同一类型只能存在一个 `QUEUED/RUNNING` 运行，但必须保留已结束运行的历史。

### 6.2 repo_inventory_versions

保存某个项目在某个 Commit 上的仓库索引。它是平台 Agent 进行 Context Plan 的输入，不等同于最终 Code Evidence。

| 字段 | 类型 | 约束/说明 |
|---|---|---|
| id | BIGINT | PK |
| project_id | BIGINT | FK projects.id |
| provider | VARCHAR(30) | `GIT` |
| repository_url | VARCHAR(500) | 同步时使用的仓库地址 |
| branch_name | VARCHAR(100) | 通常为默认分支 |
| commit_sha | VARCHAR(100) | inventory 对应的 Commit |
| status | VARCHAR(20) | `CURRENT`、`STALE`、`FAILED` |
| repository_profile | JSONB | 技术栈、目录、构建和测试摘要 |
| tree_summary | JSONB | 目录树摘要、文件类型统计、关键路径 |
| error_message | TEXT | 可为空 |
| created_at | TIMESTAMPTZ | NOT NULL |
| updated_at | TIMESTAMPTZ | NOT NULL |

建议约束：

```sql
UNIQUE (project_id, provider, branch_name, commit_sha)
CHECK (provider IN ('GIT'))
CHECK (status IN ('CURRENT', 'STALE', 'FAILED'))
```

### 6.3 repo_inventory_files

保存 inventory 中的文件元数据。首次同步应尽量覆盖全部文本/二进制路径元数据，但不要求保存全部文件内容。

| 字段 | 类型 | 约束/说明 |
|---|---|---|
| id | BIGINT | PK |
| inventory_version_id | BIGINT | FK repo_inventory_versions.id |
| path | TEXT | 仓库相对路径 |
| file_type | VARCHAR(30) | `SOURCE`、`CONFIG`、`MIGRATION`、`TEST`、`DOC`、`BINARY`、`UNKNOWN` |
| size_bytes | BIGINT | 文件大小 |
| content_hash | VARCHAR(128) | 文件内容 hash，可为空 |
| indexed_summary | TEXT | 白名单或小文件摘要，可为空 |
| created_at | TIMESTAMPTZ | NOT NULL |

建议约束：

```sql
UNIQUE (inventory_version_id, path)
```

### 6.4 code_context_plans

保存平台 Agent 基于 Intent 和 Repo Inventory 生成的取证计划。

| 字段 | 类型 | 约束/说明 |
|---|---|---|
| id | BIGINT | PK |
| project_id | BIGINT | FK projects.id |
| workflow_id | BIGINT | FK workflows.id |
| inventory_version_id | BIGINT | FK repo_inventory_versions.id |
| agent_run_id | BIGINT | FK agent_runs.id，可为空 |
| plan_json | JSONB | 要读取的文件、目录、搜索词、理由和不确定性 |
| status | VARCHAR(20) | `PROPOSED`、`USED`、`FAILED` |
| created_at | TIMESTAMPTZ | NOT NULL |

建议约束：

```sql
CHECK (status IN ('PROPOSED', 'USED', 'FAILED'))
```

### 6.5 code_context_versions

保存平台 Agent 生成文档前使用的代码上下文版本。

| 字段 | 类型 | 约束/说明 |
|---|---|---|
| id | BIGINT | PK |
| project_id | BIGINT | FK projects.id |
| provider | VARCHAR(30) | `GIT`、未来可扩展 `LOCAL_AGENT` |
| inventory_version_id | BIGINT | FK repo_inventory_versions.id，可为空 |
| context_plan_id | BIGINT | FK code_context_plans.id，可为空 |
| repository_url | VARCHAR(500) | 同步时使用的仓库地址 |
| branch_name | VARCHAR(100) | 通常为默认分支 |
| base_commit_sha | VARCHAR(100) | 该上下文对应的 Commit |
| status | VARCHAR(20) | `CURRENT`、`STALE`、`FAILED` |
| repository_profile | JSONB | 技术栈、目录、构建和测试摘要 |
| evidence_json | JSONB | 相关文件、约束、风险和证据引用 |
| error_message | TEXT | 可为空 |
| created_by | BIGINT | FK users.id，可为空；系统同步时为空 |
| created_at | TIMESTAMPTZ | NOT NULL |
| updated_at | TIMESTAMPTZ | NOT NULL |

业务约束：

- 同一项目同一 Commit 和同一 Context Plan 可以复用上下文；
- AgentRun 使用上下文后不能修改该版本内容；
- 默认分支最新 Commit 变化时，旧版本可以标记为 `STALE`；
- Provider 失败只能保存 `FAILED`，不能生成伪造证据。

建议约束：

```sql
UNIQUE (project_id, provider, branch_name, base_commit_sha, context_plan_id)
CHECK (provider IN ('GIT', 'LOCAL_AGENT'))
CHECK (status IN ('CURRENT', 'STALE', 'FAILED'))
```

### 6.6 code_context_files

保存 Code Context 中被引用的文件级证据。大文件只保存摘要、hash 和片段，不保存完整内容。

| 字段 | 类型 | 约束/说明 |

## 9. 外键和删除策略

- User：不物理删除，禁用；
- Project：不物理删除，归档；
- ProjectMember：不物理删除，标记 `REMOVED`；
- Workflow/Task：不物理删除，使用 `CANCELLED`；
- DocumentVersion、TaskPackage、CodeContextVersion、AuditLog、CIRun：保留历史；
- 删除项目成员前，必须处理其未完成任务；
- 删除项目成员不得级联删除任务、文档、审计或交付记录。
